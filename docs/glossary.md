# 用語集: Microsoft Graph によるメール取得まわり

Microsoft の製品・機能名は似たものが多く、名前も頻繁に変わるため、本リポジトリの資料に出てくる用語をなるべく平易な言葉でまとめる。
カッコ内は英語表記・旧称・画面上の別名。

---

## 1. 全体像

```
Microsoft 365 (会社向けクラウドサービス一式)
 └─ テナント (会社ごとの専用区画)  ← Microsoft Entra ID が「名簿と鍵」を管理
     ├─ ユーザー (社員のアカウント)
     │    └─ メールボックス (Exchange Online 上のメールの保管場所)
     ├─ 共有メールボックス (問い合わせ窓口など)
     └─ アプリ (本サンプルのようなプログラム)
          ├─ アプリの登録          … アプリの「設計図・プロフィール」
          └─ エンタープライズ アプリケーション … テナント内での「実体・社員証」

本サンプル ──(アクセストークン)──▶ Microsoft Graph ──▶ Exchange Online のメール
```

## 2. サービス・管理画面

| 用語 | 平易な説明 |
|---|---|
| **Microsoft 365** | Microsoft の会社向けクラウドサービス一式。メール (Exchange Online)、Teams、SharePoint などをまとめた呼び名。 |
| **Exchange Online** | Microsoft 365 の **メールサーバー**。メールボックスはここにある。Outlook はこれを使うためのメールソフト。 |
| **Outlook** | メールを読み書きするアプリ (デスクトップ版・Web 版の Outlook on the web など)。Exchange Online の「画面」にあたる。 |
| **Microsoft Entra ID** (旧称: Azure Active Directory / Azure AD) | 会社の **名簿と鍵の管理係**。誰がいるか (ユーザー)、どのアプリが何をしてよいか (権限)、サインインの確認を担当する。「Entra」と略されることが多い。 |
| **Microsoft Graph** (Graph API) | Microsoft 365 のデータ (メール・予定表・ユーザーなど) を、プログラムから読み書きするための **共通の窓口 (API)**。URL は `https://graph.microsoft.com`。 |
| **Entra 管理センター** | Entra ID を設定する管理画面 (https://entra.microsoft.com)。アプリの登録やアクセス許可はここで行う。 |
| **Azure ポータル** | Azure (Microsoft のクラウド基盤) 全体の管理画面。Entra ID の設定もここから行える。中国版では `portal.azure.cn`。 |
| **Microsoft 365 管理センター** | ライセンスの購入・ユーザー作成などを行う管理画面 (https://admin.microsoft.com)。 |
| **Exchange 管理センター** | メールまわり (メールボックス・共有メールボックスなど) の管理画面 (https://admin.exchange.microsoft.com)。 |
| **Exchange Online PowerShell** | Exchange Online をコマンドで設定するための道具。RBAC for Applications のように **管理画面ではできない設定** に使う。`Connect-ExchangeOnline` で接続する。 |

## 3. テナント・アカウント・メールボックス

| 用語 | 平易な説明 |
|---|---|
| **テナント** | 会社ごとに分けられた **専用の区画**。ユーザー・アプリ・設定はテナント単位で管理され、他社のテナントとは混ざらない。「ディレクトリ」とも呼ばれる。 |
| **テナント ID** (ディレクトリ ID) | テナントを識別する番号 (例: `316f1cbf-...`)。設定ファイルの `tenant.id`。 |
| **初期ドメイン** | テナント作成時に付く `xxx.onmicrosoft.com` 形式のドメイン (中国版は `xxx.partner.onmschina.cn`)。 |
| **職場または学校アカウント** | 会社 (テナント) が発行したアカウント。例: `user@contoso.onmicrosoft.com`。 |
| **個人用 Microsoft アカウント** | outlook.com・hotmail.com などの個人向けアカウント。テナントに属さない。設定ファイルでは `tenant.id=consumers` で指定する。 |
| **UPN** (ユーザー プリンシパル名) | ユーザーのサインイン名。通常はメールアドレスと同じ形。設定ファイルの `target.user` に指定する。 |
| **グローバル管理者** | テナントのほぼすべてを設定できる最上位の管理者。 |
| **ライセンス** | サービスの利用権。たとえば Exchange Online のライセンスを割り当てると、そのユーザーにメールボックスが作られる。ユーザーを作っただけではメールボックスはできない。 |
| **Exchange Online (Plan 1)** | メール機能だけの安価なライセンス。本サンプルの検証に使用。 |
| **メールボックス** | メールの保管場所。ユーザーごとにあり、中は受信トレイ・送信済みアイテムなどのフォルダーに分かれている。 |
| **共有メールボックス** | 複数人で使うメールボックス (問い合わせ窓口など)。ライセンス不要で作れる。直接サインインはせず、権限を与えられた人やアプリが読む。 |

## 4. アプリと認証

### 4.1 アプリの登録まわり (「Entra アプリ」と呼ばれがちなもの)

| 用語 | 平易な説明 |
|---|---|
| **アプリの登録** (App registration) | アプリを Entra ID に登録した **設計図・プロフィール**。名前・資格情報 (シークレット / 証明書)・必要な権限を設定する場所。Entra 管理センターの「アプリの登録」メニュー。 |
| **エンタープライズ アプリケーション** (サービスプリンシパル / Service Principal) | アプリの登録をもとにテナント内に作られる **実体 (社員証のようなもの)**。権限が実際に付与されるのはこちら。Entra 管理センターの「エンタープライズ アプリケーション」メニュー。 |
| **クライアント ID** (アプリケーション ID / App ID) | アプリを識別する番号。アプリの登録とエンタープライズ アプリケーションで **共通**。設定ファイルの `client.id`。 |
| **オブジェクト ID** | Entra ID 内の各データを識別する番号。**アプリの登録とエンタープライズ アプリケーションで値が異なる**。RBAC for Applications の `New-ServicePrincipal -ObjectId` には、**エンタープライズ アプリケーション側** の値を使う。 |
| **サポートされているアカウントの種類** | どのアカウントがこのアプリを使えるか (自社テナントのみ / 他社も可 / 個人アカウントも可)。 |
| **パブリック クライアント フロー** | デバイスコードフローなど、シークレットを持たないアプリのサインイン方式を許可する設定。委任アクセス (`device-code`) でのみ必要。 |

### 4.2 資格情報 (アプリが「本物」であることの証明)

| 用語 | 平易な説明 |
|---|---|
| **クライアントシークレット** | アプリ用の **パスワード**。文字列そのものを送って認証する。漏れると誰でもアプリになりすませる。有効期限は最長 2 年。 |
| **証明書** | アプリ用の **ハンコ (印鑑証明)**。秘密鍵 (ハンコ本体) はアプリが持ち、公開鍵 (印影) を Entra ID に登録する。認証時はハンコを押した書類 (署名) だけを送るので、シークレットより安全。 |
| **秘密鍵 / 公開鍵** | 証明書の鍵のペア。秘密鍵は外に出さず厳重に保管し、公開鍵は Entra ID にアップロードする。 |
| **PEM / PFX** | 証明書ファイルの形式。PEM はテキスト形式、PFX はパスワードで保護できる形式。 |
| **マネージド ID** | Azure 上で動くアプリに、シークレットも証明書も持たせずに認証させる仕組み。ローカル実行の本サンプルでは使わない。 |

### 4.3 アクセス方式とトークン

| 用語 | 平易な説明 |
|---|---|
| **委任アクセス** (Delegated) | ユーザーがサインインし、**そのユーザーの代理** でアプリが動く方式。読めるのはそのユーザー自身のメール (`/me`)。 |
| **アプリケーションアクセス** (Application / App-only) | ユーザーのサインインなしに、**アプリ自身の権限** で動く方式。権限を与えたメールボックスを読める (`/users/{UPN}`)。本サンプルの主な方式。 |
| **デバイスコードフロー** | 画面のないアプリ向けのサインイン方法。表示されたコードを、別の端末のブラウザで入力してサインインする。委任アクセス (`auth.mode=device-code`) で使用。 |
| **クライアント資格情報フロー** (Client Credentials) | アプリがシークレットや証明書だけでトークンを取る方式。アプリケーションアクセス (`client-secret` / `client-certificate`) で使用。 |
| **アクセストークン** | Graph API を呼ぶための **入館証**。Entra ID が発行し、有効期限は約 1 時間。`Authorization: Bearer <トークン>` の形で送る。 |
| **リフレッシュトークン** | アクセストークンを取り直すための長持ちする券。委任アクセスで使われる。本サンプルは保存していないため、実行のたびにサインインが必要。 |
| **スコープ** | トークンを取るときに「何をしたいか」を伝える指定。アプリケーションアクセスでは `https://graph.microsoft.com/.default` (付与済みの権限すべて) を使う。 |
| **`roles` / `scp` クレーム** | トークンの中に書かれた権限の一覧。アプリケーションアクセスは `roles`、委任アクセスは `scp` に入る。 |
| **OAuth 2.0** | アクセストークンを使う認証・認可の標準的な仕組み。上記のフローはすべてこれに基づく。 |
| **MSAL / Azure Identity** | トークン取得を代わりにやってくれる Microsoft のライブラリ。本サンプルは Azure Identity (内部で MSAL) を使っている。 |
| **AADSTS エラー** | Entra ID のサインイン・トークン取得で出るエラーコード (例: `AADSTS7000215` = シークレット誤り)。 |

## 5. 権限 (アクセス許可)

| 用語 | 平易な説明 |
|---|---|
| **アクセス許可** (API のアクセス許可 / API permissions) | アプリに「何をしてよいか」を与える設定。アプリの登録の「API のアクセス許可」で追加する。 |
| **委任されたアクセス許可** | 委任アクセス用の権限。「サインインしたユーザーができる範囲」と重なる部分だけ使える。 |
| **アプリケーションの許可** | アプリケーションアクセス用の権限。既定では **テナント内の全員** が対象になる (例: `Mail.Read` なら全員のメールを読める)。 |
| **同意** (ユーザーの同意 / 管理者の同意) | 権限をアプリに与えることへの承認。アプリケーションの許可には **管理者の同意** が必須。外すときは「管理者の同意を取り消す」→「アクセス許可の削除」の順に行う。 |
| **`Mail.Read`** | メールを読む権限 (本文・添付ファイルを含む)。 |
| **`Mail.ReadBasic`** | 本文・添付ファイルを除いて、件名・差出人・日時などだけを読む権限。 |
| **`Mail.ReadWrite` / `Mail.Send`** | メールの変更・削除 / 送信の権限。 |
| **`.Shared` / `.All` 付きの権限** | `.Shared` は「自分に共有されたメールボックスも対象」(委任のみ)、`.All` は「全メールボックスが対象」(アプリケーション用) を表す。 |

## 6. メールボックスを絞る仕組み (Exchange 側の権限)

| 用語 | 平易な説明 |
|---|---|
| **RBAC** (ロールベースのアクセス制御) | 「役割 (ロール)」単位で権限を与える仕組み。誰に・どの役割を・どの範囲で、を組み合わせて管理する。 |
| **RBAC for Applications** | Exchange Online の RBAC を **アプリ向け** に使う機能。アプリが読めるメールボックスを、Exchange 側で限定できる。Entra ID のアプリケーションの許可と **足し算** で評価される。 |
| **管理ロール** (例: `Application Mail.Read`) | 「何をしてよいか」をまとめた役割。`Application Mail.Read` は Graph の `Mail.Read` に相当する。 |
| **管理スコープ** | 「どのメールボックスが対象か」の条件 (例: カスタム属性が `GraphMailAllowed` のメールボックス)。 |
| **ロールの割り当て** | 「アプリ」に「ロール」を「スコープ」付きで結び付ける設定 (`New-ManagementRoleAssignment`)。 |
| **カスタム属性** (CustomAttribute1〜15) | メールボックスに自由に付けられる目印。スコープの条件に使う。 |
| **管理単位** (Administrative Unit) | Entra ID でユーザーをまとめるグループのような単位。スコープの条件にも使える。 |
| **Application Access Policy** | RBAC for Applications の **前身** (旧方式)。アプリが読めるメールボックスをグループで制限する。 |
| **組織のカスタマイズ** (`Enable-OrganizationCustomization`) | Exchange の高度な設定を使えるようにする、テナントで 1 回だけの準備作業。新しいテナントではスコープ作成の前に必要。 |

## 7. セキュリティ設定

| 用語 | 平易な説明 |
|---|---|
| **セキュリティの既定値群** (Security defaults) | Microsoft が用意した **基本の安全設定セット** (多要素認証の必須化など)。新しいテナントでは有効になっており、デバイスコードフローでのサインインもブロックされる。 |
| **条件付きアクセス** | 「どの条件ならサインインを許可するか」を細かく決める仕組み。Entra ID P1 などの有料ライセンスが必要。 |
| **多要素認証** (MFA) | パスワードに加えてスマホアプリなどで本人確認する仕組み。 |
| **Entra ID P1 / P2** | Entra ID の有料プラン。条件付きアクセスなどの高度な機能が使える。 |

## 8. Graph API・メール取得

| 用語 | 平易な説明 |
|---|---|
| **API** | プログラム同士がやり取りするための窓口・決まりごと。 |
| **エンドポイント** | API の接続先の URL (例: `https://graph.microsoft.com/v1.0/users/{UPN}/messages`)。 |
| **v1.0 / beta** | Graph API の版。v1.0 は本番用で安定、beta は試験版で予告なく変わる。 |
| **SDK** | API を使いやすくするための部品集 (ライブラリ)。本サンプルは Microsoft Graph Java SDK を使用。 |
| **クエリパラメーター** (`$select` / `$filter` / `$orderby` / `$top`) | 取得する項目・絞り込み条件・並び順・件数の指定。 |
| **既定のフォルダー名** (`inbox` / `sentitems` など) | 受信トレイ・送信済みアイテムなど、最初からあるフォルダーをプログラムから指定する名前。画面の表示名は言語で変わるため、こちらを使う。 |
| **送信トレイ / 送信済みアイテム** | 送信トレイ (`outbox`) は送信待ちのメールが一時的に入る場所。送ったメールが入るのは送信済みアイテム (`sentitems`)。 |
| **`receivedDateTime` / `sentDateTime`** | メールの受信日時 / 送信日時。本サンプルは `receivedDateTime` を「メールの日時」として使う。 |
| **`parentFolderId`** | メールが入っているフォルダーの ID。 |
| **delta クエリ** (差分取得) | 前回からの変更分だけを取得する仕組み。メールの delta は中国版では使えない。 |
| **ODataError** | Graph API がエラー (403 など) を返したときのエラー情報の形式。 |

## 10. 混同しやすい用語

| 混同しやすい組み合わせ | 違い |
|---|---|
| アプリの登録 ⇔ エンタープライズ アプリケーション | 登録は「設計図・プロフィール」、エンタープライズ アプリケーションは「テナント内の実体」。どちらも「Entra のアプリ」と呼ばれがち。 |
| クライアント ID ⇔ オブジェクト ID | クライアント ID はアプリ共通の番号。オブジェクト ID は登録とエンタープライズ アプリケーションで別々の番号。 |
| 委任アクセス ⇔ アプリケーションアクセス | ユーザーの代理で動く (サインインあり) ⇔ アプリ自身の権限で動く (サインインなし)。 |
| 委任されたアクセス許可 ⇔ アプリケーションの許可 | 同じ `Mail.Read` でも、前者は自分のメールだけ、後者は全員のメールが対象。 |
| Entra ID のアプリケーションの許可 ⇔ RBAC for Applications | 前者は Entra 側で付ける全メールボックス対象の権限、後者は Exchange 側で付ける範囲限定の権限。両方あると足し算になる。 |
| テナント ID ⇔ ドメイン | テナント ID は番号 (`316f1cbf-...`)、ドメインはメールアドレスの `@` 以降 (`xxx.onmicrosoft.com`)。 |
| シークレット ID ⇔ シークレットの値 | 設定に使うのは「値」。ID は管理用の番号。 |
| 送信トレイ ⇔ 送信済みアイテム | 送信待ち ⇔ 送信済み。 |
