# 用語集: Microsoft Graph によるメール取得まわり

Microsoft の製品・機能名は似たものが多く、名前もよく変わるため、平易な言葉でまとめる。カッコ内は英語表記・旧称・別名。

---

## 1. 全体像

```
Microsoft 365
 └─ テナント (会社ごとの専用区画)  ← Microsoft Entra ID が「名簿と鍵」を管理
     ├─ ユーザー ─ メールボックス (Exchange Online 上)
     ├─ 共有メールボックス
     └─ アプリ
          ├─ アプリの登録 (設計図・プロフィール)
          └─ エンタープライズ アプリケーション (テナント内の実体)

アプリ ──(アクセストークン)──▶ Microsoft Graph ──▶ Exchange Online のメール
```

---

## 2. サービス・管理画面

| 用語 | 説明 |
|---|---|
| **Microsoft 365** | Microsoft の会社向けクラウドサービス一式 (メール・Teams・SharePoint など)。 |
| **Exchange Online** | Microsoft 365 のメールサーバー。メールボックスはここにある。 |
| **Outlook** | メールを読み書きするアプリ。Exchange Online の画面にあたる。 |
| **Microsoft Entra ID** (旧称: Azure Active Directory / Azure AD) | 会社の **名簿と鍵の管理係**。ユーザー・アプリ・権限・サインインを管理する。 |
| **Microsoft Graph** (Graph API) | Microsoft 365 のデータをプログラムから読み書きする共通の窓口 (API)。 |
| **Entra 管理センター** | Entra ID の管理画面。アプリの登録やアクセス許可を設定する。 |
| **Azure ポータル** | Azure (Microsoft のクラウド基盤) の管理画面。Entra ID の設定もできる。 |
| **Microsoft 365 管理センター** | ライセンスやユーザーを管理する画面。 |
| **Exchange 管理センター** | メールボックスなど、メールまわりを管理する画面。 |
| **Exchange Online PowerShell** | Exchange Online をコマンドで設定する道具。管理画面でできない設定 (RBAC for Applications など) に使う。 |

## 3. テナント・アカウント・メールボックス

| 用語 | 説明 |
|---|---|
| **テナント** (ディレクトリ) | 会社ごとの **専用区画**。ユーザー・アプリ・設定はテナント単位で管理される。 |
| **テナント ID** | テナントを識別する番号 (GUID)。 |
| **初期ドメイン** | テナント作成時に付く `xxx.onmicrosoft.com` 形式のドメイン。 |
| **職場または学校アカウント** | テナント (会社) が発行したアカウント。 |
| **個人用 Microsoft アカウント** | outlook.com などの個人向けアカウント。テナントに属さない。 |
| **UPN** (ユーザー プリンシパル名) | ユーザーのサインイン名。通常はメールアドレスと同じ形。 |
| **グローバル管理者** | テナントのほぼすべてを設定できる最上位の管理者。 |
| **ライセンス** | サービスの利用権。Exchange Online のライセンスを割り当てると、そのユーザーにメールボックスが作られる。 |
| **Exchange Online (Plan 1)** | メール機能だけの安価なライセンス。 |
| **メールボックス** | メールの保管場所。中は受信トレイ・送信済みアイテムなどのフォルダーに分かれている。 |
| **共有メールボックス** | 複数人で使うメールボックス (問い合わせ窓口など)。ライセンス不要。 |

## 4. アプリと認証

### 4.1 アプリの登録 (「Entra のアプリ」と呼ばれがちなもの)

| 用語 | 説明 |
|---|---|
| **アプリの登録** (App registration) | アプリの **設計図・プロフィール**。名前・資格情報・必要な権限を設定する。 |
| **エンタープライズ アプリケーション** (サービスプリンシパル) | アプリの登録をもとにテナント内に作られる **実体**。権限が実際に付与されるのはこちら。 |
| **クライアント ID** (アプリケーション ID) | アプリを識別する番号。アプリの登録とエンタープライズ アプリケーションで共通。 |
| **オブジェクト ID** | Entra ID 内の各データの番号。アプリの登録とエンタープライズ アプリケーションで **値が異なる**。 |
| **サポートされているアカウントの種類** | どのアカウントがアプリを使えるか (自社テナントのみ / 他社も可 / 個人アカウントも可)。 |
| **パブリック クライアント フロー** | シークレットを持たないアプリ (デバイスコードフローなど) のサインインを許可する設定。 |

### 4.2 資格情報 (アプリが本物であることの証明)

| 用語 | 説明 |
|---|---|
| **クライアントシークレット** | アプリ用の **パスワード**。文字列そのものを送って認証するため、漏れると誰でもなりすませる。 |
| **証明書** | アプリ用の **ハンコ**。秘密鍵 (ハンコ本体) はアプリが持ち、公開鍵 (印影) を Entra ID に登録する。署名だけを送るので、シークレットより安全。 |
| **PEM / PFX** | 証明書ファイルの形式。PFX はパスワードで保護できる。 |
| **マネージド ID** | Azure 上で動くアプリが、シークレットも証明書も持たずに認証できる仕組み。 |

### 4.3 アクセス方式とトークン

| 用語 | 説明 |
|---|---|
| **委任アクセス** (Delegated) | ユーザーがサインインし、**そのユーザーの代理** でアプリが動く方式。 |
| **アプリケーションアクセス** (Application / App-only) | サインインなしに **アプリ自身の権限** で動く方式。 |
| **デバイスコードフロー** | 表示されたコードを別の端末のブラウザで入力してサインインする方法 (委任アクセス)。 |
| **クライアント資格情報フロー** (Client Credentials) | シークレットや証明書だけでトークンを取る方法 (アプリケーションアクセス)。 |
| **アクセストークン** | Graph API を呼ぶための **入館証**。有効期限は約 1 時間。 |
| **リフレッシュトークン** | アクセストークンを取り直すための長持ちする券 (委任アクセス)。 |
| **スコープ** | トークン取得時に伝える「何をしたいか」。アプリケーションアクセスでは `.default` (付与済みの権限すべて) を使う。 |
| **`roles` / `scp` クレーム** | トークン内の権限の一覧。アプリケーションアクセスは `roles`、委任アクセスは `scp`。 |
| **OAuth 2.0** | トークンを使う認証・認可の標準的な仕組み。 |
| **MSAL / Azure Identity** | トークン取得を担う Microsoft のライブラリ。 |
| **AADSTS エラー** | Entra ID のサインイン・トークン取得で出るエラーコード。 |

## 5. 権限 (アクセス許可)

| 用語 | 説明 |
|---|---|
| **アクセス許可** (API のアクセス許可) | アプリに「何をしてよいか」を与える設定。 |
| **委任されたアクセス許可** | 委任アクセス用。サインインしたユーザーができる範囲でだけ使える。 |
| **アプリケーションの許可** | アプリケーションアクセス用。既定では **テナント内の全員** が対象。 |
| **同意** (ユーザーの同意 / 管理者の同意) | 権限をアプリに与えることへの承認。アプリケーションの許可には管理者の同意が必須。 |
| **`Mail.Read` / `Mail.ReadBasic`** | メールを読む権限。ReadBasic は本文・添付ファイルを除く。 |
| **`Mail.ReadWrite` / `Mail.Send`** | メールの変更・削除 / 送信の権限。 |
| **`.Shared` / `.All`** | `.Shared` は共有されたメールボックスも対象 (委任のみ)、`.All` は全メールボックスが対象 (アプリケーション用)。 |

## 6. メールボックスを絞る仕組み (Exchange 側の権限)

| 用語 | 説明 |
|---|---|
| **RBAC** (ロールベースのアクセス制御) | 「役割 (ロール)」単位で権限を与える仕組み。 |
| **RBAC for Applications** | Exchange Online の RBAC をアプリ向けに使う機能。アプリが読めるメールボックスを Exchange 側で限定できる。Entra ID のアプリケーションの許可とは足し算で評価される。 |
| **管理ロール** | 「何をしてよいか」の役割 (例: `Application Mail.Read`)。 |
| **管理スコープ** | 「どのメールボックスが対象か」の条件。 |
| **カスタム属性** | メールボックスに自由に付けられる目印。スコープの条件に使う。 |
| **管理単位** (Administrative Unit) | Entra ID でユーザーをまとめる単位。スコープの条件にも使える。 |
| **Application Access Policy** | RBAC for Applications の前身 (旧方式)。 |
| **組織のカスタマイズ** (`Enable-OrganizationCustomization`) | Exchange の高度な設定を使うための、テナントで 1 回だけの準備作業。 |

## 7. セキュリティ設定

| 用語 | 説明 |
|---|---|
| **セキュリティの既定値群** (Security defaults) | Microsoft が用意した基本の安全設定セット。多要素認証の必須化や、デバイスコードフローのブロックなどを含む。 |
| **条件付きアクセス** | サインインを許可する条件を細かく決める仕組み。Entra ID P1 などの有料プランが必要。 |
| **多要素認証** (MFA) | パスワードに加え、スマホアプリなどで本人確認する仕組み。 |

## 8. Graph API・メール取得

| 用語 | 説明 |
|---|---|
| **エンドポイント** | API の接続先 URL。 |
| **v1.0 / beta** | Graph API の版。v1.0 は本番用、beta は試験版で予告なく変わる。 |
| **SDK** | API を使いやすくするためのライブラリ。 |
| **クエリパラメーター** (`$select` / `$filter` / `$orderby` / `$top`) | 取得する項目・絞り込み・並び順・件数の指定。 |
| **既定のフォルダー名** (`inbox` / `sentitems` など) | 最初からあるフォルダーをプログラムから指定する名前。画面の表示名は言語で変わる。 |
| **`receivedDateTime` / `sentDateTime`** | メールの受信日時 / 送信日時。送信済みメールの `receivedDateTime` には送信日時が入る。 |
| **`parentFolderId`** | メールが入っているフォルダーの ID。 |
| **delta クエリ** | 前回からの変更分だけを取得する仕組み。 |

## 10. 混同しやすい用語

| 組み合わせ | 違い |
|---|---|
| アプリの登録 ⇔ エンタープライズ アプリケーション | 設計図 ⇔ テナント内の実体。どちらも「Entra のアプリ」と呼ばれがち。 |
| クライアント ID ⇔ オブジェクト ID | 前者は両者で共通、後者は別々の値。 |
| 委任されたアクセス許可 ⇔ アプリケーションの許可 | 同じ `Mail.Read` でも、前者は自分のメールだけ、後者は全員のメールが対象。 |
| Entra ID のアプリケーションの許可 ⇔ RBAC for Applications | 前者は全メールボックス対象、後者は範囲を限定できる。両方あると足し算。 |
| テナント ID ⇔ ドメイン | 番号 ⇔ メールアドレスの `@` 以降。 |
| シークレット ID ⇔ シークレットの値 | 認証に使うのは値。ID は管理用の番号。 |
| 送信トレイ ⇔ 送信済みアイテム | 送信待ち ⇔ 送信済み。 |
