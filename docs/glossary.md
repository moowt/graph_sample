# 用語集: Microsoft Graph によるメール取得まわり

Microsoft の製品・機能名は似たものが多く、名前もよく変わるため、平易な言葉でまとめる。カッコ内は英語表記・旧称・別名。
「関連用語」には、あわせて理解しておくとよい用語を絞って記載する。

---

## 1. 全体像

```
Microsoft 365
 └─ テナント (会社ごとの専用区画)  ← Microsoft Entra ID が「名簿と鍵」を管理
     ├─ ユーザー ─ メールボックス (Exchange Online 上)
     ├─ 共有メールボックス
     └─ アプリ
          ├─ アプリの登録 (設計図・プロフィール。資格情報を設定する)
          └─ エンタープライズ アプリケーション (テナント内の実体)

アプリ ──(資格情報で認証)──▶ Entra ID ──(アクセストークン発行)──▶ アプリ
アプリ ──(アクセストークン)──▶ Microsoft Graph ──▶ Exchange Online のメール
```

---

## 2. サービス・管理画面

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **Microsoft 365** | Microsoft の会社向けクラウドサービス一式 (メール・Teams・SharePoint など)。 | テナント |
| **Exchange Online** | Microsoft 365 のメールサーバー。メールボックスはここにある。 | メールボックス、Outlook |
| **Outlook** | メールを読み書きするアプリ。Exchange Online の画面にあたる。 | Exchange Online |
| **Microsoft Entra ID** (旧称: Azure Active Directory / Azure AD) | 会社の **名簿と鍵の管理係**。ユーザー・アプリ・権限・サインインを管理する。 | テナント、アプリの登録 |
| **Microsoft Graph** (Graph API) | Microsoft 365 のデータをプログラムから読み書きする共通の窓口 (API)。 | アクセストークン、アクセス許可 |
| **Entra 管理センター** | Entra ID の管理画面。アプリの登録やアクセス許可を設定する。 | Azure ポータル |
| **Azure ポータル** | Azure (Microsoft のクラウド基盤) の管理画面。Entra ID の設定もできる。 | Entra 管理センター |
| **Microsoft 365 管理センター** | ライセンスやユーザーを管理する画面。 | ライセンス |
| **Exchange 管理センター** | メールボックスなど、メールまわりを管理する画面。 | 共有メールボックス |
| **Exchange Online PowerShell** | Exchange Online をコマンドで設定する道具。管理画面でできない設定に使う。 | RBAC for Applications |

## 3. テナント・アカウント・メールボックス

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **テナント** (ディレクトリ) | 会社ごとの **専用区画**。ユーザー・アプリ・設定はテナント単位で管理される。 | テナント ID、初期ドメイン |
| **テナント ID** | テナントを識別する番号 (GUID)。 | テナント |
| **初期ドメイン** | テナント作成時に付く `xxx.onmicrosoft.com` 形式のドメイン。 | テナント、UPN |
| **職場または学校アカウント** | テナント (会社) が発行したアカウント。 | 個人用 Microsoft アカウント |
| **個人用 Microsoft アカウント** | outlook.com などの個人向けアカウント。テナントに属さない。 | 職場または学校アカウント |
| **UPN** (ユーザー プリンシパル名) | ユーザーのサインイン名。通常はメールアドレスと同じ形。 | - |
| **グローバル管理者** | テナントのほぼすべてを設定できる最上位の管理者。 | 管理者の同意 |
| **ライセンス** | サービスの利用権。Exchange Online のライセンスを割り当てると、そのユーザーにメールボックスが作られる。 | Exchange Online (Plan 1) |
| **Exchange Online (Plan 1)** | メール機能だけの安価なライセンス。 | ライセンス |
| **メールボックス** | メールの保管場所。中は受信トレイ・送信済みアイテムなどのフォルダーに分かれている。 | 共有メールボックス、既定のフォルダー名 |
| **共有メールボックス** | 複数人で使うメールボックス (問い合わせ窓口など)。ライセンス不要。 | メールボックス |

## 4. アプリと認証

### 4.1 アプリの登録 (「Entra のアプリ」と呼ばれがちなもの)

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **アプリの登録** (App registration) | アプリの **設計図・プロフィール**。名前・資格情報・必要な権限を設定する。 | エンタープライズ アプリケーション、資格情報 |
| **エンタープライズ アプリケーション** (サービスプリンシパル) | アプリの登録をもとにテナント内に作られる **実体**。権限が実際に付与されるのはこちら。 | アプリの登録、オブジェクト ID |
| **クライアント ID** (アプリケーション ID) | アプリを識別する番号。アプリの登録とエンタープライズ アプリケーションで共通。 | オブジェクト ID |
| **オブジェクト ID** | Entra ID 内の各データの番号。アプリの登録とエンタープライズ アプリケーションで **値が異なる**。 | クライアント ID |
| **サポートされているアカウントの種類** | どのアカウントがアプリを使えるか (自社テナントのみ / 他社も可 / 個人アカウントも可)。 | 個人用 Microsoft アカウント |
| **パブリック クライアント フロー** | シークレットを持たないアプリ (デバイスコードフローなど) のサインインを許可する設定。 | デバイスコードフロー |

### 4.2 資格情報 (アプリが本物であることの証明)

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **資格情報** (Credential) | アプリが **本物であることを証明するもの** の総称。アプリケーションアクセスでは、クライアントシークレットか証明書のどちらかを使う。アプリの登録の「証明書とシークレット」で設定する。 | クライアントシークレット、証明書 |
| **クライアントシークレット** (シークレット) | アプリ用の **パスワード**。文字列そのものを送って認証するため、漏れると誰でもなりすませる。有効期限 (最長 2 年) がある。 | 資格情報、証明書 |
| **シークレットの値 / シークレット ID** | 作成したシークレットに表示される 2 つの値。認証に使うのは「値」で、作成直後の画面でしか確認できない。ID は管理用の番号。 | クライアントシークレット |
| **証明書** | アプリ用の **ハンコ**。秘密鍵 (ハンコ本体) はアプリが持ち、公開鍵 (印影) を Entra ID に登録する。署名だけを送るので、シークレットより安全。有効期限がある。 | 資格情報、秘密鍵 / 公開鍵 |
| **秘密鍵 / 公開鍵** | 証明書の鍵のペア。秘密鍵は外に出さず厳重に保管し、公開鍵だけを Entra ID にアップロードする。 | 証明書 |
| **自己署名証明書** | 認証局を通さず自分で作った証明書。Entra ID のアプリ認証ではこれで問題ない。 | 証明書 |
| **PEM / PFX** | 証明書ファイルの形式。PFX はパスワードで保護できる。 | 証明書 |
| **マネージド ID** | Azure 上で動くアプリが、シークレットも証明書も持たずに認証できる仕組み。 | 資格情報 |

### 4.3 アクセス方式とトークン

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **委任アクセス** (Delegated) | ユーザーがサインインし、**そのユーザーの代理** でアプリが動く方式。 | 委任されたアクセス許可、デバイスコードフロー |
| **アプリケーションアクセス** (Application / App-only) | サインインなしに **アプリ自身の権限** で動く方式。 | アプリケーションの許可、クライアント資格情報フロー |
| **デバイスコードフロー** | 表示されたコードを別の端末のブラウザで入力してサインインする方法 (委任アクセス)。 | パブリック クライアント フロー、セキュリティの既定値群 |
| **クライアント資格情報フロー** (Client Credentials) | 資格情報 (シークレットや証明書) だけでトークンを取る方法 (アプリケーションアクセス)。 | 資格情報、アクセストークン |
| **アクセストークン** | Graph API を呼ぶための **入館証**。資格情報で認証した結果として発行され、有効期限は約 1 時間。 | 資格情報、スコープ |
| **リフレッシュトークン** | アクセストークンを取り直すための長持ちする券 (委任アクセス)。 | アクセストークン |
| **スコープ** | トークン取得時に伝える「何をしたいか」。アプリケーションアクセスでは `.default` (付与済みの権限すべて) を使う。 | アクセス許可 |
| **`roles` / `scp` クレーム** | トークン内の権限の一覧。アプリケーションアクセスは `roles`、委任アクセスは `scp`。 | アクセストークン |
| **OAuth 2.0** | トークンを使う認証・認可の標準的な仕組み。 | - |
| **MSAL / Azure Identity** | トークン取得を担う Microsoft のライブラリ。 | - |
| **AADSTS エラー** | Entra ID のサインイン・トークン取得で出るエラーコード。 | - |

## 5. 権限 (アクセス許可)

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **アクセス許可** (API のアクセス許可) | アプリに「何をしてよいか」を与える設定。 | 同意、スコープ |
| **委任されたアクセス許可** | 委任アクセス用。サインインしたユーザーができる範囲でだけ使える。 | 委任アクセス |
| **アプリケーションの許可** | アプリケーションアクセス用。既定では **テナント内の全員** が対象。 | アプリケーションアクセス、RBAC for Applications |
| **同意** (ユーザーの同意 / 管理者の同意) | 権限をアプリに与えることへの承認。アプリケーションの許可には管理者の同意が必須。 | アクセス許可 |
| **`Mail.Read` / `Mail.ReadBasic`** | メールを読む権限。ReadBasic は本文・添付ファイルを除く。 | アクセス許可 |
| **`Mail.ReadWrite` / `Mail.Send`** | メールの変更・削除 / 送信の権限。 | アクセス許可 |
| **`.Shared` / `.All`** | `.Shared` は共有されたメールボックスも対象 (委任のみ)、`.All` は全メールボックスが対象 (アプリケーション用)。 | - |

## 6. メールボックスを絞る仕組み (Exchange 側の権限)

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **RBAC** (ロールベースのアクセス制御) | 「役割 (ロール)」単位で権限を与える仕組み。 | 管理ロール |
| **RBAC for Applications** | Exchange Online の RBAC をアプリ向けに使う機能。アプリが読めるメールボックスを Exchange 側で限定できる。Entra ID のアプリケーションの許可とは足し算で評価される。 | 管理ロール、管理スコープ |
| **管理ロール** | 「何をしてよいか」の役割 (例: `Application Mail.Read`)。 | 管理スコープ |
| **管理スコープ** | 「どのメールボックスが対象か」の条件。 | カスタム属性、管理単位 |
| **カスタム属性** | メールボックスに自由に付けられる目印。スコープの条件に使う。 | 管理スコープ |
| **管理単位** (Administrative Unit) | Entra ID でユーザーをまとめる単位。スコープの条件にも使える。 | 管理スコープ |
| **Application Access Policy** | RBAC for Applications の前身 (旧方式)。 | RBAC for Applications |
| **組織のカスタマイズ** (`Enable-OrganizationCustomization`) | Exchange の高度な設定を使うための、テナントで 1 回だけの準備作業。 | 管理スコープ |

## 7. セキュリティ設定

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **セキュリティの既定値群** (Security defaults) | Microsoft が用意した基本の安全設定セット。多要素認証の必須化や、デバイスコードフローのブロックなどを含む。 | 多要素認証、条件付きアクセス |
| **条件付きアクセス** | サインインを許可する条件を細かく決める仕組み。Entra ID P1 などの有料プランが必要。 | セキュリティの既定値群 |
| **多要素認証** (MFA) | パスワードに加え、スマホアプリなどで本人確認する仕組み。 | - |

## 8. Graph API・メール取得

| 用語 | 説明 | 関連用語 |
|---|---|---|
| **エンドポイント** | API の接続先 URL。 | - |

## 10. 混同しやすい用語

| 組み合わせ | 違い |
|---|---|
| アプリの登録 ⇔ エンタープライズ アプリケーション | 設計図 ⇔ テナント内の実体。どちらも「Entra のアプリ」と呼ばれがち。 |
| クライアント ID ⇔ オブジェクト ID | 前者は両者で共通、後者は別々の値。 |
| 資格情報 ⇔ アクセストークン | 資格情報は「アプリが本物である証明」(長期間使う)。アクセストークンは、その証明で受け取る「入館証」(約 1 時間で切れる)。 |
| クライアントシークレット ⇔ 証明書 | パスワードそのものを送る ⇔ ハンコで署名したものだけを送る。 |
| シークレット ID ⇔ シークレットの値 | 認証に使うのは値。ID は管理用の番号。 |
| 委任されたアクセス許可 ⇔ アプリケーションの許可 | 同じ `Mail.Read` でも、前者は自分のメールだけ、後者は全員のメールが対象。 |
| Entra ID のアプリケーションの許可 ⇔ RBAC for Applications | 前者は全メールボックス対象、後者は範囲を限定できる。両方あると足し算。 |
| テナント ID ⇔ ドメイン | 番号 ⇔ メールアドレスの `@` 以降。 |
| 送信トレイ ⇔ 送信済みアイテム | 送信待ち ⇔ 送信済み。 |
